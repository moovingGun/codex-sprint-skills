# AGENTS.md — 150분 웹 서비스 개발

프로젝트 루트에서 기존 지침과 병합해 사용한다. README와 실제 제한 시간이 우선한다.

## 목적과 시간표 — 이 표가 단일 기준
제한 시간 내 실행 가능한 필수 웹 서비스와 제출물을 완성한다.
시작 시각과 남은 시간을 기록하고, 중간에 작업을 이어받아도 시계를 다시 시작하지 않는다.

| 경과 시간 | 작업 |
|---|---|
| 0~10분 | README 요구 체크리스트·담당자 질문·익숙한 스택 결정 |
| 10~25분 | 앱·DB·로그인·/health 실행 골격, Docker·의존성 사용 가능 여부 확인 |
| 25~105분 | 필수 수직 흐름 구현. 관련 검증기·작은 테스트를 기능과 함께 작성 |
| 105~125분 | 최종 코드의 Docker 기동 + 핵심 통합 확인을 한 번에 수행, 필수 오류 수정 |
| 125~140분 | 실행 문서·협업 회고·출처·Skill·세션 히스토리·제출 형식 확인 |
| 140~150분 | 필수 수정·제출 버퍼. 수정 영향만 재확인하고 실제 제출 |

전체 서비스 완성이 우선이다. 검증기 전체·모든 테스트 완성을 구현의 선행 조건으로 삼지 않는다.
105분부터 새 부가 기능·UI 다듬기·큰 리팩터링을 멈춘다. 필수 누락은 기록하고 우선 해결한다.
이해도 문답·예상 질문은 기본 흐름에서 제외한다. 명시 요청이 있을 때만 별도로 수행한다.

## Skill 사용
시작: sprint-writing-plans. 기능 구현: sprint-test-driven-development와
sprint-property-based-testing의 필요한 부분만 적용한다. Docker 골격은 일찍 준비하고
sprint-docker-compose의 최종 확인은 sprint-verification과 같은 실행에서 합친다.
같은 검사·문서·fixture를 Skill별로 다시 만들지 않는다.
사용자 요청 범위 안의 작업은 계속하되 실행 권한·대회 환경 제한을 따른다.

## 최소 구조
- 브라우저 → API → DB. 브라우저에서 DB에 직접 접속하지 않는다.
- 유지되어야 하는 데이터·결과·작업 상태는 DB에 둔다. 불필요한 큐·서비스는 추가하지 않는다.
- 긴 계산이 필요할 때만 워커를 둔다. 플래너와 검증기의 제약 판정은 독립적으로 작성한다.
- 전체 입력 검증 후 트랜잭션으로 적용하고 실패 시 기존 데이터·결과·버전을 유지한다.
- 계산은 입력 버전을 고정한다. 결과 공개 시 현재 버전과 맞는지 확인하고,
  불일치하면 이전 결과로 표시하거나 재계산 필요 상태로 둔다.
- 중복 실행은 서버/DB에서 막고 오류·빈 결과·실행 중을 구분한다.
- API 재기동으로 다른 프로세스의 running 작업을 일괄 failed 처리하지 않는다.
  단일 실행 주체가 보장된 경우만 단순 중단 정리를 쓰고, 워커가 있으면 소유권을 확인한다.
- 권한은 서버에서 검사한다. 설정·비밀값은 환경변수, .env.example은 안전한 예시로 둔다.
- 빈 DB 초기화는 멱등하게 하고 DB 준비 후 앱/워커가 동작하도록 최소 연결 재시도를 둔다.

## 꼭 필요한 검증과 재실행
- 정상 흐름 + 독립 검증 + 실제 export JSON 스키마. 출력 파손 2종 거부.
- 잘못된 스키마·참조 ID 거부와 기존 데이터·결과·버전 유지.
- 데이터 교체·계산 중 버전 변경, 중복 요청·오류·빈 입력의 최소 사례.
- 비로그인·다른 역할의 API 직접 호출 거부.
과제에 해당하는 범주만 작은 fixture와 기존 API 테스트로 묶고, 과제의 추가 필수 검사는 따른다.

| 상황 | 다시 확인할 범위 |
|---|---|
| 기능 구현·버그 수정 | 해당 테스트 + 수정 영향이 있는 검사 |
| 공용 파서·스키마·DB·권한·직렬화 변경 | 연결된 핵심 테스트 묶음 |
| Docker·의존성·기동 설정 변경 | 해당 서비스의 build/기동/health |
| 통과 이후 관련 변경 없음, 단순 문서 수정 | 기존 근거 재사용, 앱·Docker 검사 생략 |
| 제출 전 | 핵심 통합 확인 1회. 빠른 전체 검사가 포함하면 그 명령으로 대체 |

검사 기록에 명령·요구·결과·검사 이후 변경을 짧게 남긴다.
검사 횟수·커버리지 목표, 장시간 전체 검사, 랜덤·완전탐색·변이 캠페인은 강제하지 않는다.
실패·미실행을 통과로 바꾸지 않는다. 기존 데이터 삭제와 DB 초기화를 반복하지 않는다.

## 짧은 기록과 제출
README 원문은 유지한다. REQUIREMENTS.md는 요구·구현·상태·근거만 짧게 적는다.
DECISIONS.md와 AI 협업 메모는 중요한 선택·대안·이유만 남긴다.
HOW_TO_RUN.md, 실제 문항에 맞춘 AI_COLLABORATION.md, AGENTS.md, 사용 Skill 전체,
출처·커밋·라이선스·수정 내역과 실제 세션 히스토리를 제출 가이드에 맞게 포함한다.
허위 경험과 실행 결과를 만들지 않는다. 과제·데이터·제출물을 공개 저장소에 올리지 않는다.
