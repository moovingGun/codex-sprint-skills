- 제공된 README.md는 과제 지시문이다. 수정·교체하지 않는다.

- 시간이 밀리면 UI 다듬기·부가 기능을 먼저 줄인다. 필수 테스트와 실행 가능 상태는 줄이지 않는다.

## 기본 구조
- 브라우저 → 웹 API → DB. 브라우저는 DB에 직접 붙지 않는다.
- API는 stateless. 세션·작업 상태·결과를 포함한 모든 상태는 DB에 둔다.
- 생성기(플래너)와 결과 검증기는 분리하고 서로 import하지 않는다. 검증을 통과한 결과만 저장한다.
- 데이터셋 적용은 전체 검증 후 하나의 트랜잭션으로 한다. 실패하면 기존 데이터·결과를 유지한다.
- 결과에 입력 데이터 버전을 저장한다. 현재 버전과 다르면 "재계산 필요"로 표시하고 이전 결과를 새 결과처럼 보여 주지 않는다.
- 생성 작업은 상태(pending/running/done/failed)를 DB에 둔다. 중복 실행은 서버에서 거부하고, 기동 시 running으로 남은 작업은 failed로 정리한다.
- 권한은 서버(API)에서 검사한다. UI에서 버튼을 숨기는 것만으로 처리하지 않는다.
- 설정·비밀값은 환경변수로만 읽고 .env.example을 둔다. /health는 DB 연결까지 확인한다.
- 오류와 빈 결과를 구분한다. (예: 근무자 0명인 날은 오류가 아니라 "운행 없음")

## 검증 (LITE)
- 필수 테스트 4개: 검증기 정상 통과 / 출력 파손 2종 거부 / 잘못된 데이터셋 거부 + 기존 결과 유지 / 비로그인·타 역할 API 거부
- 해 품질은 하한 대비 수치로 표시한다.
- 랜덤 property test, 완전탐색, 변이 테스트, compose 재시작 시나리오는 하지 않는다.
- 전체 테스트와 docker compose up → /health 확인은 마지막에 1회.
