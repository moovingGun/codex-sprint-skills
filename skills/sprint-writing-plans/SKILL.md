# Sprint Writing Plans (LITE)

Modified adaptation, 2026-11-04. Source, revision, and changes: [ATTRIBUTION.md](ATTRIBUTION.md).
목표는 제한 시간 안에 실행 가능한 필수 웹 서비스를 완성하는 것이다.
계획과 검증을 독립된 큰 프로젝트로 만들지 않는다.

## 시작: 최대 10분
README를 읽고 REQUIREMENTS.md를 만든다.

| ID | 요구·수락 조건 (한 줄) | 구현 파일 | 상태·근거 |
|---|---|---|---|

- TODO / DONE / VERIFIED / BLOCKED. 실제 확인한 것만 VERIFIED로 표시한다.
- 과제에 없는 규칙·스키마를 만들지 않는다. 가정과 담당자 답변을 구분한다.
- 구현 위치는 처음에는 비워두고 구현할 때 채운다. 문서를 길게 쓰지 않는다.
- 설계를 바꾸는 모호함만 담당자에게 묶어 질문하고, 독립 작업은 계속한다.

## 시간과 실행 순서
프로젝트 AGENTS.md의 시간표가 있으면 그것을 단일 기준으로 따른다.
없으면 150분을 계획 10 / 실행 골격 15 / 필수 구현 80 / 최종 통합 20 /
제출 문서 15 / 수정·제출 버퍼 10분으로 배분한다. 이미 지난 시간부터 다시 시작하지 않는다.
사용자가 정한 다른 제한 시간이 있으면 그 시간과 남은 시간에 맞춰 조정한다.

- 익숙한 스택으로 앱·DB·로그인·/health의 최소 실행 골격부터 연결한다.
- Docker와 의존성 사용 가능 여부를 초기에 짧게 확인해 마지막의 설치 문제를 줄인다.
- 입력 적용 → 계산 → 저장 → 조회 → 정확한 JSON 출력의 수직 흐름을 만든다.
  권한은 관련 API를 만들 때 넣는다. 모든 구현 뒤로 미루지 않는다.
- 검증기와 테스트는 관련 기능과 함께 최소 단위로 작성한다.
  구현 전에 검증기 전체와 모든 테스트를 완성하느라 시간을 소비하지 않는다.
- 워커·큐·추가 서비스는 과제와 실행시간상 필요할 때만 추가한다.
- 105분 이후에는 필수 누락과 오류 수정에 집중하고 UI 다듬기·큰 리팩터링을 멈춘다.
  미완료 필수 기능은 숨기지 않는다.

## 짧은 작업 기록
DECISIONS.md는 중요한 선택부터 `선택 / 대안 / 이유`로 짧게 기록한다.
AI 제안의 채택·수정·폐기는 그때 한 줄 메모해 회고 재료로 쓴다. 경험을 지어내지 않는다.
검사 결과는 명령·관련 요구·결과·검사 이후 바뀐 파일만 기록한다.
통과했고 관련 변경이 없는 검사는 다시 하지 않는다.
예상 질문·이해도 연습은 기본 계획에 넣지 않는다.

실행 스크립트·외부 서비스·다른 Skill 의존성이 없다.
