# Sprint Property-Based Testing

Modified adaptation, 2026-11-04. Source, revision, and changes: [ATTRIBUTION.md](ATTRIBUTION.md).
Adapted from Trail of Bits contributors; this adaptation is CC-BY-SA-4.0.

## 검증할 성질 선택
구현 코드보다 요구 계약에서 성질을 먼저 도출한다.
- invariant: 필수 제약이 변환 전후 또는 결과 전체에서 성립한다.
- oracle: 작은 입력의 결과를 독립 참조 구현이나 완전탐색 정답과 비교한다.
- roundtrip: 허용된 동등성 아래 decode(encode(x))가 x와 같다.
- idempotence: 정규화를 반복해도 결과가 같다.
구조적으로 맞지 않는 성질을 강요하지 않는다. 무작위 생성 없이 예제·경계값
테스트만으로 충분하면 그 방법을 쓰고 검증 범위를 명시한다.

## 독립성
복잡한 생성기/플래너와 결과 검증기의 제약 판정 함수를 분리한다.
파서·자료형은 공유할 수 있지만, 동일한 버그를 공유하는 규칙 함수를 호출하여
맞다고 판정하지 않는다. 원입력과 최종 출력으로 제약과 목적값을 다시 계산한다.
주장을 다음 세 가지로 나눈다.
1. 형식 유효성: 스키마·타입·필수 키·유효한 참조.
2. 실행 가능성: 모든 필수 제약 충족 여부.
3. 해 품질: 목적값, 기준선/하한 비교와 계산 시간.
실행 가능하다고 최적이라고 말하지 않는다.

## 입력과 반례
기존 Hypothesis/fast-check 등이 있으면 활용한다. 없다면 표준 라이브러리의
시드 고정 생성과 명시적 경계 사례로 시작할 수 있다. 새 의존성은 필요할 때만
프로젝트에서 허용된 방식으로 도입하고, 설치 제한이 있으면 대체 방법을 사용한다.
- 빈 입력, 최소 크기, 제한값 바로 아래/같음/바로 위를 포함한다.
- 유효 데이터 생성과 무효 데이터 생성을 구분한다.
- assume/filter로 대부분을 제외하는 공허한 테스트를 피한다.
- 실패 시 seed뿐 아니라 실제 입력·출력·버전·오류를 저장한다.
- 원래 실패를 유지하면서 반례를 줄인다. 실패한 assertion의 타당성도 확인한다.

## 검증기를 깨뜨려 보기
정상 결과가 수락되는지 먼저 확인한다.
그 결과에 중복·누락·무효 참조·제한 초과·타입 오류·목적값 변조를 과제에 맞게
하나씩 주입한다. 검증기가 해당 위반을 이유와 함께 거부하는지 확인한다.
거부했다고 충분하지 않다. 무관한 파싱 오류 때문에 실패한 것은 아닌지 확인한다.
입력 부정 테스트, 출력 파손 테스트, 코드 변이 테스트를 구분해 기록한다.

## 소형 정답과 품질
완전탐색은 작은 범위로 제한하고 탐색한 후보·제약·목적함수를 명시한다.
동일한 최적값을 가진 다른 해가 가능하므로 배열 전체 동일성을 강제하지 않는다.
하한은 방향과 가정이 증명 가능한 경우에만 사용한다. 최솟값 문제와 최댓값 문제의
비교 방향을 구분하고, 하한이 0일 때 비율 계산도 명시적으로 처리한다.
결과 보고에는 표본 범위·시드/반례·명령·실패·확인하지 못한 조건을 남긴다.
실행 스크립트·필수 외부 서비스·다른 Skill 의존성이 없다.
