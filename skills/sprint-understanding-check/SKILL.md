# Sprint Understanding Check (LITE)

Original work, 2026-11-04. License: [LICENSE](LICENSE).
항상 LITE 모드로 동작한다. 총 10분 이내. 완성 답안을 쓰지 않고 뼈대와 근거 위치만 정리한다.

## 목적
제출 후 평가자가 제출물을 읽고 "만든 사람이 이해하고 있는가"를 묻는 질문에 대비한다.
사람이 외울 문장이 아니라, 답할 때 떠올릴 근거를 정리한다.

## 산출물: UNDERSTANDING.md
제출물에 포함해도 되는지 규정을 확인한다. 애매하면 작업 디렉터리 밖에 둔다.

### 예상 질문 6개
아래 유형마다 이번 구현에 맞춘 질문 1개를 만든다.
1. 설계 선택: 목적함수·탐색 방식(또는 핵심 알고리즘)을 왜 골랐고, 대안 대비 무엇을 얻고 포기했나
2. 구조와 상태: 버튼 하나의 요청이 어떤 구성요소를 어떤 순서로 거치고, 상태는 어디에 있나
3. 데이터 적용: 잘못된 입력이 기존 데이터를 망가뜨리지 않게 한 방법, 이전 결과와 새 결과의 구분
4. 실패 처리: 빈 입력·실행 중 오류·중복 실행·재시작 시 화면 표시와 처리
5. 결과 신뢰: AI 설명이 아닌 근거(검증기·테스트·하한), 규모·조건이 바뀔 때의 병목과 개선
6. AI 협업: AI_COLLABORATION.md에 쓴 사례에서 전달한 것, 채택·수정·폐기한 것과 그 근거

### 질문마다 4줄
- 결정: (무엇을 했나, 한 줄)
- 이유: (README 요구·담당자 답변·제약 중 무엇 때문인가)
- 근거: (파일·함수·테스트 이름·실행 결과)
- 한계: (안 된 것, 하려면 어떻게)

코드와 기록에서 직접 확인한 내용만 적는다. 확인 못 하면 "미확인"이라고 적는다.

## 구멍 찾기 (3분)
HOW_TO_RUN.md와 AI_COLLABORATION.md의 주장 중 코드·테스트·기록으로 뒷받침되지 않는 것을 나열한다.
문서를 실제에 맞게 고치도록 제안한다. 없는 구현이나 경험을 문서에 맞춰 만들어내지 않는다.

## 마지막 1분
사람에게 6개 중 가장 자신 없는 질문 2개를 고르게 하고, 그 질문의 근거 파일을 한 번 더 짚어 준다.

## 범위
실행 스크립트·외부 서비스·다른 Skill 의존성이 없다. 과제 원문이나 실제 제출물을 이 저장소에 두지 않는다.
