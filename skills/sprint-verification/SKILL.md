# Sprint Verification (LITE)

Modified adaptation, 2026-11-04. Source, revision, and changes: [ATTRIBUTION.md](ATTRIBUTION.md).
목표는 제한 시간 내 필수 웹 서비스와 제출물을 완성하는 것이다.
검증 때문에 처음부터 다시 구현하거나 모든 검사를 매번 반복하지 않는다.
시간 배분은 프로젝트 AGENTS.md를 따른다. 이해도 문답은 이 흐름에 포함하지 않는다.

## 재사용할 근거
짧은 검사 기록에서 명령·요구·결과·검사 이후 변경을 확인한다.
통과 이후 관련 변경이 없으면 근거를 재사용한다. 변경이 있으면 그 영향만 다시 확인한다.
최종 확인 뒤 코드 수정이 없고 문서만 바뀌었다면 앱·Docker 검사를 반복하지 않는다.
공용 파서·스키마·DB·권한·직렬화가 바뀌면 연결된 핵심 묶음을 다시 확인한다.
실패를 수정했다면 재현 테스트 + 영향받는 검사만 실행한다. assertion을 약하게 바꾸지 않는다.

## 핵심 통합 확인: 한 번
Docker 기동 검사와 앱 검사를 같은 실행에서 묶어 다음을 확인한다.
- /health와 정상 입력 적용 → 계산 → 독립 검증 → 조회 → 실제 export JSON 스키마.
- 잘못된 입력의 거부와 기존 데이터·결과·버전 보존.
- 데이터 교체 후 이전 결과 구분, 계산 중 버전 변경·중복 실행·오류·빈 입력의 처리.
- 비로그인·다른 역할의 직접 API 접근 거부.
기존 자동 테스트와 짧은 API 확인을 재사용한다. 긴 새 검증 체계를 만들지 않는다.
빠른 전체 검사가 이 묶음을 포함하면 한 명령으로 대체하고 같은 검사를 두 번 하지 않는다.
장시간 전체 검사·커버리지·무작위 테스트·완전탐색·정교한 복구 실험은 기본 범위에서 제외한다.
미실행·시간 초과·실패는 통과로 적지 않는다. 이미 확인한 항목부터 처음으로 되돌아가지 않는다.

## 체크리스트와 제출 문서
- README와 REQUIREMENTS.md를 대조하고 필수 누락을 먼저 확인한다.
  UI 개선·추가 기능은 멈추고 실행 불가·채점 계약 오류를 우선 수정한다.
- HOW_TO_RUN.md의 명령·환경변수·접속·계정·빈 DB 초기화·영속화·테스트·출력이
  실제 실행과 맞는지 확인한다. 같은 명령을 문서 확인 명목으로 다시 실행할 필요는 없다.
- AI_COLLABORATION.md는 제공된 문항과 실제 채택·수정·폐기 메모로 작성한다.
  문항·경험을 지어내지 않는다.
- 실제 사용한 Skill 폴더(LICENSE·ATTRIBUTION 포함), 출처·사용 커밋·수정 내역과
  AGENTS.md를 제출 범위에 포함한다.
- 환경이 허용하는 방법으로 실제 세션 히스토리를 보존·포함한다. 회고로 대체하지 않는다.
- 제출 형식·파일 위치·내보내기 방법은 상세 가이드를 따른다.

최종 보고는 통과 / 실패 / 미실행 / 미완료를 요구 ID와 함께 짧게 남긴다.
남은 제한은 공개하고 비밀값·불필요한 개인정보는 기록하지 않는다.
실행 스크립트·외부 서비스·다른 Skill 의존성이 없다.
