# Sprint Verification

Modified adaptation, 2026-11-04. Source, revision, and changes: [ATTRIBUTION.md](ATTRIBUTION.md).

## 근거 있는 완료
확신, AI 설명, 코드 존재, 다른 에이전트의 성공 보고만으로 완료라 하지 않는다.
최종 변경 이후의 실제 명령·출력·종료 상태와 확인한 요구를 연결한다.
과거 실행 결과는 어떤 버전의 결과인지 명시한다. 이후 코드가 바뀌었다면 영향을
받는 검사를 다시 수행한다. 변화나 새 의심 없이 같은 전체 검사를 반복하지 않는다.

## 요구사항 대조
README와 제공된 운영 조건을 다시 읽는다.
REQUIREMENTS.md가 없으면 요구 ID | 구현 파일·심볼 | 검증 | 결과 표를 만든다.
각 요구를 VERIFIED / FAILED / NOT RUN / INCOMPLETE로 구분한다.
테스트 통과를 요구 전체 충족과 동일시하지 않는다.
특히 다음 경계를 실제 과제에 맞게 확인한다.
- 입력 검증 실패 시 기존 데이터와 결과 보존.
- 새 입력과 이전 결과의 버전 구분 및 계산 중 입력 변경.
- 빈 데이터, 오류, 중복 요청, 재실행, 재시작의 명시된 처리.
- 비로그인·다른 역할의 직접 API 호출 차단.
- 계산 결과의 독립 제약 검증과 정확한 출력 스키마.
- 서버 권한과 UI 권한 표시의 일치.

## 검사 실행
프로젝트가 지정한 lint/typecheck/test/build 중 적용되는 명령을 실행한다.
전체 테스트와 실제 앱의 최소 통합 흐름을 확인한다.
테스트가 없다면 성공이라고 하지 말고 실행해 확인한 범위를 명시한다.
네트워크·Docker·브라우저가 제한되면 제한된 검사와 대체 근거를 구분한다.
깨진 테스트를 통과시키려고 assertion·요구·오류 처리를 약화하지 않는다.
실패는 원인과 영향부터 확인하고 필요한 수정 후 관련 검사를 다시 실행한다.

## 실행과 제출 문서
HOW_TO_RUN.md의 명령을 허용된 깨끗한 테스트 DB/환경에서 재현한다.
환경변수, .env.example, 빈 DB 초기화, 영속화, healthcheck, 접속, 테스트,
결과 출력 방법이 실제 코드와 일치하는지 확인한다.
환경 초기화를 위해 기존 사용자 데이터를 삭제하지 않는다.

AI_COLLABORATION.md는 제공된 문항 원문과 실제 작업 기록으로 작성한다.
무엇을 전달하고 무엇을 채택·수정·폐기했는지 증거와 연결한다.
문항 원문이나 경험이 없으면 확인 필요로 표시하고 만들어내지 않는다.
AGENTS.md와 실제 사용한 Skill 전체·출처·커밋·수정 내역·라이선스를 포함한다.
공식적으로 요구된 실제 세션 히스토리를 보존하며 회고로 대체하지 않는다.

## 최종 보고
통과: 명령과 실제 결과.
실패/미실행/미완료: 요구 ID, 영향, 이유와 남은 조치.
계산의 실행 가능성·해 품질·최적성은 각각 확인한 범위만 주장한다.
미완료가 있으면 제출 준비 완료로 표현하지 않는다.
검증 기록에는 비밀값이나 불필요한 개인정보를 넣지 않는다.
실행 스크립트·외부 서비스·다른 Skill 의존성이 없다.
